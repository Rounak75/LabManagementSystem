Codebase Architecture Review

Deepening opportunities for testability and navigability.

1. Cloud Sync Adapter Deepening

apps/desktop/src/main/services/cloud/supabase-client.ts

Strong Recommendation

Problem (Shallow Module)

The current Supabase client interface is extremely shallow. It exposes an individual fetch*Since method for every domain concept (fetchBookingsSince, fetchDisputesSince, fetchPatientsSince, etc.). This breaks locality: adding a new synced entity requires modifying the client interface, the implementation, and the sync engine, rather than leveraging a dynamic seam.

Solution

Consolidate the pull mechanism behind a deep SyncAdapter interface that accepts a generic entity configuration. By moving the table name and timestamp column metadata out of the method names and into a sync registry, we create a true seam. The client implementation becomes a single pullSince(tableName, cursorColumn, sinceIso).

Benefits

Increases leverage (adding a new synced table requires zero changes to the cloud client). Improves testability by allowing us to mock a single boundary method for all entities. Concentrates complexity applying the deletion test successfully.

2. Token Validator Interface

apps/admin/src/lib/auth-session.ts

Worth Exploring

Problem (Friction)

The Admin app parses its custom JWT manually using jose inside utility functions. The crypto logic is tangled with the cookie parsing and DB lookup (session_epoch). This lacks a clear seam for testing and makes migrating auth providers difficult.

Solution

Extract a TokenValidator interface that handles the cryptographic verification independently of the Next.js cookie/request context. Inject this validator into the session retrieval logic.
